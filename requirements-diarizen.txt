# Dependencies of the SEPARATE diarizen environment — more accurate speaker labelling.
#
# why a separate environment. diarizen brings its own fork of pyannote-audio 3.1.1, while the
# main pipeline runs on pyannote.audio 4.x. it is the same namespace package: only one of them
# can be installed in one environment. measured — when they are made to share a place, pyannote
# as a fallback labeller, speaker refinement against voice references and plda all fall away.
# so diarizen lives on its own, and the pipeline calls it as a subprocess and gets back plain
# json with a list of turns.
#
# python 3.10 is required: on 3.13 numpy 1.26.4, which diarizen is pinned to, does not build.
# diarizen's own pins ask for torch 2.1.1 + CUDA 12.1, but that build does not support cards
# newer than Ada (Blackwell, RTX 50xx). so a current torch is installed instead and the
# mismatches are patched over in tools/diarize_diarizen.py.
#
# --------------------------------------------------------------------------------
# full installation (uv brings its own python; conda or a venv on your own 3.10 work too):
#
#   git clone https://github.com/BUTSpeechFIT/DiariZen.git
#   uv venv --python 3.10 /path/to/diarizen-venv
#   PY=/path/to/diarizen-venv/bin/python        # windows: ...\Scripts\python.exe
#
#   uv pip install --python $PY torch torchaudio \
#       --index-url https://download.pytorch.org/whl/cu130
#   uv pip install --python $PY -r requirements-diarizen.txt
#   uv pip install --python $PY --no-deps -e ./DiariZen/pyannote-audio -e ./DiariZen
#
# the last line installs the library itself and its pyannote fork — from source only, there is
# no diarizen package on pypi. --no-deps is required: without it pip pulls the old pins back.
#
# then point this at the interpreter and the pipeline picks diarizen up by itself:
#   export DIARIZEN_PYTHON=$PY                  # windows: set DIARIZEN_PYTHON=...
# --------------------------------------------------------------------------------
